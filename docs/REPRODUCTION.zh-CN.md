# 简单复现记录

## 复现目标

在 `1ur-xiaoxiao/masaic_task` 的 `1.py` 基础上，用真实的小型照片素材库生成一张照片马赛克，并让新手可以在 Windows 的 VS Code 中再次运行。

开始时仓库包含 `README.md` 和用户上传的 `1.py`，基线提交为 `40ffa5bdfabf65bcb1b1cb743d0f0db671a3f804`。

没有改变原来的 RGB 差异平方和匹配算法。每个候选素材和目标区域缩到 5×5，比较对应 RGB 像素，选总差异最小的素材，再把它的 50×50 版本放到输出位置。

### 尺寸问题的具体例子

原图 203×157，放大 8 倍后是 1624×1256，裁成 1600×1250。输出块是 50×50，所以横向有 32 块；每个匹配块宽 5，匹配图就应宽 160。

原代码仍用裁剪前的宽 1624 计算匹配图，得到宽 162，因此匹配区域与输出区域逐渐错位。修正后读取 `large_img.size`，匹配图为 160×125，对应输出的 32×25 个块。

## 实际操作顺序

1. 克隆仓库并更新到用户上传 `1.py` 的提交，检查原代码的图片读取、缩放、匹配和多进程流程。
2. 加入前面准备的 Oxford 17 Flowers 小样本；目标原图不在素材库内。
3. 修正尺寸同步，加入默认路径、错误说明和完成等待，保留原算法与主要类结构。
4. 加入 VS Code 配置、依赖清单、使用教程和三个回归检查。
5. 运行 `python -m unittest discover -s tests -v`：三个检查全部通过。
6. 从项目外的工作目录启动 `python <项目绝对路径>/1.py`：退出码为 0，约 2.15 秒，自动生成结果。
7. 读取并查看实际输出：RGB JPEG，1600×1200，32×24 共 768 块；将该结果复制为 `docs/sample_result.jpg` 供仓库预览。
8. 按教程创建全新的 `.venv` 并安装 `requirements.txt`，在该环境中再次运行三个检查和示例，全部成功；确认输出与仓库预览的 SHA-256 一致，调试配置 JSON 可解析，目标图路径不存在时返回退出码 1。
